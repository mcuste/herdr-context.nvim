1. Overview                                         *herdr-context-overview*

herdr-context.nvim places the current file, every open file, a Visual
selection, or the reported diagnostics in a coding agent's input inside Herdr.
It formats the file reference for that agent, focuses the agent, and leaves
the text unsubmitted.

The plugin prefers agents in the current Herdr tab. It falls back to agents in
the current workspace and opens |vim.ui.select()| when several agents remain.

The plugin does not write the current buffer, start an agent, or press Enter
in the target pane.

==============================================================================
2. Requirements                                 *herdr-context-requirements*

- Neovim 0.10 or later.
- Herdr 0.7.5 or later.
- Neovim running inside a Herdr pane.
- A current file that exists on disk.

Herdr must provide $HERDR_WORKSPACE_ID and $HERDR_TAB_ID. The `herdr`
executable must be on $PATH.

Run |:checkhealth| after installation. See |herdr-context-health|.

3. Setup                                               *herdr-context-setup*

Call setup once: >lua

  require('herdr-context').setup({
    mappings = {
      buffer = '<leader>aa',
      buffers = '<leader>aA',
      diagnostics = '<leader>ad',
      buffers_diagnostics = '<leader>aD',
    },
  })
<
The complete default configuration is: >lua

  {
    mappings = {
      buffer = '',
      buffers = '',
      diagnostics = '',
      buffers_diagnostics = '',
    },
  }
<
All mappings are disabled by default. Setup always creates the user commands.
Each mapping applies in Normal mode and Visual mode.

                                                   *herdr-context-mappings*
`mappings.buffer` ~
    Normal-mode and Visual-mode mapping for |herdr-context.send_buffer()|. An
    empty string disables it.

`mappings.buffers` ~
    Normal-mode and Visual-mode mapping for |herdr-context.send_buffers()|. An
    empty string disables it. Give it a key of its own, because it applies in
    both modes.

`mappings.diagnostics` ~
    Normal-mode and Visual-mode mapping for
    |herdr-context.send_diagnostics()|. An empty string disables it. Give it a
    key of its own, because it applies in both modes.

`mappings.buffers_diagnostics` ~
    Normal-mode and Visual-mode mapping for
    |herdr-context.send_buffers_diagnostics()|. An empty string disables it.
    Give it a key of its own, because it applies in both modes.

Mapping values must be strings. Invalid values make setup fail before it
replaces the current configuration.

==============================================================================
4. Commands                                         *herdr-context-commands*

                                               *:HerdrContextSendBuffer*
:[range]HerdrContextSendBuffer ~
    Place a reference to the current saved file or Visual selection in a Herdr
    agent's input.

                                              *:HerdrContextSendBuffers*
:[range]HerdrContextSendBuffers ~
    Place a reference to every open saved file in a Herdr agent's input. The
    current file uses the Visual selection when the command runs in Visual
    mode or with a range.

                                          *:HerdrContextSendDiagnostics*
:[range]HerdrContextSendDiagnostics ~
    Place a reference to the current saved file, or to the Visual selection,
    followed by one reference for every diagnostic in it. In Visual mode, or
    with a range, only diagnostics in the selected lines are placed.

                                    *:HerdrContextSendBuffersDiagnostics*
:[range]HerdrContextSendBuffersDiagnostics ~
    Place a reference to every open saved file, each one followed by the
    diagnostics in that file. In Visual mode, or with a range, the current
    file uses the selection and only its diagnostics in the selected lines.

All commands focus the selected agent after successful text placement. They
never submit the input.

==============================================================================
5. Lua API                                               *herdr-context-api*

setup({config})                            *herdr-context.setup()*
    Validate configuration, create all commands, and create configured
    mappings. `{config}` can be omitted.

send_buffer()                         *herdr-context.send_buffer()*
    Place a reference to the current saved file or Visual selection.

send_buffers()                       *herdr-context.send_buffers()*
    Place a reference to every open saved file, in buffer order. The current
    file uses the Visual selection when one is active.


send_diagnostics()               *herdr-context.send_diagnostics()*
    Place a reference to the current saved file, or to the Visual selection,
    followed by one reference for every diagnostic in it.

send_buffers_diagnostics() *herdr-context.send_buffers_diagnostics()*
    Place a reference to every open saved file, each one followed by the
    diagnostics in that file.

All operations are asynchronous after editor input has been validated.
Failures are reported through |vim.notify()|.

6. Files, selections, and diagnostics              *herdr-context-selections*

Every operation requires a normal file buffer whose path exists on disk.

CURRENT BUFFER ~

The whole-file operation sends only a file reference. It refuses a modified
buffer because the path would point the agent at older content on disk.

ALL OPEN BUFFERS ~

The all-files operation sends one reference for every listed buffer that is
saved on disk, in buffer order, with each file on its own line. Buffers that
Neovim has not loaded yet are included, for example files from the command
line. It skips a buffer with unsaved changes, without a file, or with a
special buffer type, and reports how many buffers it skipped. It stops when no
buffer remains.

Only the current buffer can carry a selection. In Visual mode, or with an Ex
range, the current file follows the selection rules below and the other files
send whole-file references. An invalid selection stops the operation and
reports the reason.

COMPLETE LINES ~

A complete-line selection sends a file reference with an inclusive range. It
also refuses a modified buffer.

PARTIAL LINES AND BLOCKS ~

A characterwise or blockwise selection that does not contain complete lines
sends the ranged reference followed by the exact selected text in a fenced
code block. The buffer filetype becomes the fence language.

Partial and block selections allow unsaved changes because the current text is
included. The file itself must still exist on disk.

When selected text contains backticks, the plugin uses a longer fence so the
text cannot close it.

DIAGNOSTICS ~

The diagnostics operation places one line for each diagnostic that Neovim
reports. It reads the diagnostics with |vim.diagnostic.get()|, so every source
that publishes into Neovim is included.

Each diagnostic line holds the ranged reference, the severity name, the
message on one line, and the source and code when Neovim has them:

   @lua/plugin.lua#L18-20 ERROR undefined global `value` [lua_ls]

The line already names the file and the range, so no separate file reference
is placed. A partial or block selection does not add its fenced text either.

In Visual mode, or with an Ex range, only diagnostics whose line range
overlaps the selected lines are placed.

The operation refuses a modified buffer, also for a partial selection, because
a diagnostic is placed as a line reference and the line numbers must match the
file on disk. It stops when the buffer or the selection has no diagnostic.

Diagnostics are sorted by start line, then by severity, then by message, so
the same buffer always produces the same text.

ALL OPEN BUFFERS WITH DIAGNOSTICS ~

The all-files diagnostics operation uses the same buffer list as the all-files
operation. It places the diagnostics of each file in buffer order. A file with
no diagnostic keeps its plain file reference, so the file list stays
complete.

The current buffer can carry a selection, and then only the diagnostics in the
selected lines are placed for that file. The operation stops when no open file
has a diagnostic.

7. Agent routing                                       *herdr-context-routing*

The plugin chooses an agent in this order:

1. Read $HERDR_WORKSPACE_ID and $HERDR_TAB_ID.
2. Run `herdr agent list`.
3. Keep agents in the current workspace.
4. Prefer agents in the current tab when any exist.
5. Use all workspace agents when the current tab has none.
6. Use the only remaining agent without a picker.
7. Run `herdr tab list --workspace <id>` when several agents remain.
8. Open |vim.ui.select()| with those agents.
9. Validate the selected pane before placing text.

Current-tab preference is strict. A blocked agent in the current tab is
refused instead of silently sending the input to another tab.

PICKER ~

herdr-context.nvim uses the generic |vim.ui.select()| API. Neovim supplies the
default UI. A UI plugin can replace it. There is no picker-specific
integration.

Rows use this form:

  [n]  status  Agent: harness  Tab: name  Title: title  CWD: directory

`Title` and `CWD` are omitted when Herdr does not provide them. Pane
identifiers stay internal. Candidates follow tab-list order and then pane
identifier order. Cancelling the picker sends nothing.

Status markers are:

  blocked, working, done   ●
  idle                     ○
  missing or unknown       ·

DELIVERY ~

After choosing a target, the plugin runs:

1. `herdr pane send-text <pane-id> <text>`
2. `herdr agent focus <pane-id>`

Focus starts only after successful text placement.

8. File reference formats                           *herdr-context-formats*

The path is relative to the agent's foreground working directory when the file
is below it. The agent working directory is the second choice. The absolute
path is used when neither directory contains the file.

Formats for `lua/plugin.lua`:

Agent          Whole file              Lines 18 through 42 ~
OMP            ` @lua/plugin.lua `     ` @lua/plugin.lua#L18-42 `
Pi             ` @lua/plugin.lua `     ` @lua/plugin.lua#L18-42 `
Claude Code    ` @lua/plugin.lua `     ` @lua/plugin.lua#18-42 `
opencode       ` @lua/plugin.lua `     ` @lua/plugin.lua#18-42 `
Antigravity    ` @lua/plugin.lua `     ` @lua/plugin.lua Lines 18-42. `
Codex          ` lua/plugin.lua `      ` lua/plugin.lua Lines 18-42. `
Unknown        ` @lua/plugin.lua `     ` @lua/plugin.lua Lines 18-42. `

Every reference starts and ends with one space. Codex paths that contain
spaces are enclosed in double quotes.

Unknown agent types use the generic format instead of failing.

==============================================================================
9. Failure behavior                                 *herdr-context-failures*

The plugin stops before each dependent action:

- An invalid buffer, missing file, or disallowed unsaved change runs no Herdr
  command.
- No open buffer saved on disk runs no Herdr command.
- No diagnostic in the buffer, the selection, or the open files runs no Herdr
  command.
- An invalid selection in the current buffer runs no Herdr command.
- Missing Herdr environment values run no Herdr command.
- An agent-list failure stops routing, placement, and focus.
- A tab-list failure stops the picker, placement, and focus.
- Picker cancellation stops placement and focus without a notification.
- An invalid or blocked target stops placement and focus.
- A text-placement failure stops focus.
- A focus failure leaves the placed text in the target input.

The plugin does not retry or choose a different agent after a selected target
fails validation.

==============================================================================
10. Health and troubleshooting                       *herdr-context-health*

Run: >vim

  :checkhealth herdr-context
<
The check reports:

- The Neovim version.
- The Herdr executable and version.
- $HERDR_WORKSPACE_ID and $HERDR_TAB_ID.
- The `herdr agent list` result.
- The `herdr tab list --workspace <id>` result when a workspace ID exists.

COMMANDS ARE MISSING ~

Call |herdr-context.setup()| after the plugin loads.

HERDR ENVIRONMENT IS MISSING ~

Start Neovim inside a Herdr pane. Starting Neovim in a separate terminal does
not set the workspace and tab variables.

THE PLUGIN REPORTS UNSAVED CHANGES ~

Write the buffer before sending a whole-file or whole-line reference. A
partial selection can include current unsaved text.

THE AGENT RECEIVES AN ABSOLUTE PATH ~

Herdr did not report a working directory that contains the file. Check the
agent's current directory.

TEXT WAS PLACED BUT THE PANE DID NOT FOCUS ~

The placement succeeded and the later focus command failed. The text remains
in the target input.

For more detail, see `README.md`, `docs/behavior.md`, and
`docs/development.md` in the repository.
